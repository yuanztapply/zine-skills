# 从成品 PDF 导出逐页 PNG

只在已有确定的 PDF 页面、需要图片交付时使用本流程。它不生成或改写刊内文字，也不是对照片的创造性编辑工具。

## 先判断裁边语义

- 只要图片：按页面真实范围导出，不另加外框；无需自动裁设计留白。
- 用户要求去白边：通常去连续外围纸白／导出残边，保留内部空白和页码。先看实际页面；若裁边会破坏有意的版式或用户要求统一尺寸，集中澄清有歧义的部分，再处理独立的其他修改。
- 全页摄影：不要把天空、白墙等画面亮部当成外框。
- 全文、页码纳入边界，小号文字和抗锯齿需少量安全距离；按像素尺寸调整，不能永远用8px。
- 裁边后各PNG可能不同宽高；不要仍宣称是一套统一A5印刷页。若需要印刷版，另行处理出血、拼版等要求。

## 可选脚本

依赖 Python、Pillow、pypdf，以及系统可执行的 `pdftoppm`。优先使用当前环境已配置的文档运行时；缺依赖时不要凭旧环境路径假定可用。

```bash
python scripts/export_pages.py input.pdf --out-dir output/png --dpi 240
```

明确要求去外围纸白、且已核对纸底色时：

```bash
python scripts/export_pages.py input.pdf --out-dir output/png --dpi 240 \
  --trim-outer --paper '#F0F0EC' --tolerance 6 --padding-px 8 \
  --no-trim-pages 4 --zip output/pngs.zip
```

这里仅示例将第4页作为满版摄影页，跳过按纸白裁边；页号按实际情况填写。脚本不理解照片语义，不能盲用一次全册白色阈值识别天空。纸底色、容差和安全距离也以本次材料为准。

默认不覆盖既有交付，只有明确要覆盖时使用 `--overwrite`。脚本先在临时目录完整渲染；默认保留渲染器完整像素范围。只有实看确认最末行／列属于取整残边时才加 `--drop-partial-edge`，否则部分像素也可能包含真实边缘内容。随后仅在未跳过的页面按需裁连续外围纸底；不从图片内部删除白色、不生成场景。纯纸页保留全页，不生成空图片。

`--drop-partial-edge` 是全局选项，也会作用于 `--no-trim-pages` 中的页；应逐页确认后才启用，不能把“跳过纸白裁切”误解为跳过所有边缘处理。

输出按数值页序命名 `page-01.png` 等，另存 `export-manifest.json`，ZIP只含本次PNG。页号位数随总页数增加；读取工具的实际输出文件名，不假定它一定是 `-01` 或 `-1`。

## 交付前检查

打开每一张**最终导出**：文字完整、图像真实、页序正确、页面数字保留、人物不贴边或被截断、颜色符合指定范围。检查ZIP完整且仅含本次图片。DPI只是栅格化采样参数，不意味着低清剧照被变成真实高清。

已授权的图像色调／局部编辑应在源素材层完成，再回到排版重导出；不要让图像工具重绘整页，以免原句、字体和页码被悄悄改动。
